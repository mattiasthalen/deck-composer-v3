# ADR-0009 — Categories are detected by patterns in a versioned file, corrected by lists only where a miss is a violation, and locked by a golden

**Status:** Accepted (2026-09-20)

## Context

[ADR-0002](0002-the-builder-asserts-no-fact-about-its-own-picks.md) requires every
category `check` reports to be derived from card facts rather than from labels the
composer applied. It does not say how.

Two categories decide violations: extra turns and mass land denial, both capped at
zero by Bracket 2. Several more are metrics only: removal, draw, ramp, sweepers.

Run against the owned pool, candidate patterns for the two violation categories
return zero hits and zero false positives, consistent with the collection holding
no card of either kind. Zero hits also means the owned pool cannot show whether
those patterns are correct.

The collection is 603 closed names, which makes exhaustive review of a pattern's
hits and misses a one-off task rather than an ongoing one.

## Decision

**Patterns detect every category**, matched over type line and oracle text across
every face.

**Patterns live in a versioned data file** carrying the WotC document they came
from and the date it was read. Bracket criteria are WotC's data rather than this
project's logic, and a table needs to be able to say which bracket definition it
was built under.

**House metric targets live in a separate file** from the bracket patterns. A WotC
update and a change of taste have different authorities and different cadences, and
should not edit the same file.

**Include and exclude lists of exact names correct a pattern, for violation
categories only.** A missed violation is a legality failure and needs a correction
path. Metric categories get no correction lists: they never block, approximate is
adequate, and maintaining lists for removal, draw and ramp is work with no payoff.

**A golden over the owned pool locks category membership.** A pattern edit shows as
a diff and fails until the golden is regenerated by an explicit command. Nothing
regenerates it automatically on failure.

**Patterns with no owned example are tested against a committed known-positive
fixture** — cards such as Time Warp, Time Stretch, Armageddon and Ruination,
fetched once from Scryfall. The golden covers the pool; the fixture covers the
patterns the pool cannot exercise.

Rejected: exact name lists as the primary mechanism. An empty list never fires, so
a newly acquired extra-turn card would enter the collection and nothing would
notice. Both violation lists are empty today, which is exactly the condition under
which this failure is invisible.

Rejected: patterns in code. It loses the provenance of which bracket definition
applied to a given table.

## Consequences

A correction to a violation category is a data edit rather than a release.

**A category definition states which card types it excludes.** A land that taps for
mana is the mana base, not ramp, and a pattern matching the text that produces mana
will otherwise count every nonbasic land: 17 names and 32 copies in this collection,
enough to make every deck read as overwhelmingly ramp-heavy. The exclusion lives in
the category's own definition in the data file, so correcting one stays a data edit.
This is a definitional edge rather than a pattern bug, and it will recur for any
category whose text appears on both a spell and a land.

Regenerating the golden is a deliberate act that puts a diff in front of a human.
This is the mechanism that keeps the detection honest, and it stops working the
moment regeneration becomes automatic.

The known-positive fixture must be maintained by hand. It is small, and without it
the two violation patterns are untested assertions.
